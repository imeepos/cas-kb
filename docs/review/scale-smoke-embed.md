## 7. 结论

1. **rebuild --embed 在 2000 条的真实成本**:墙钟 **163.3s(≈2.7 分钟)**,单条均耗 **81.6ms**(批大小 32 摊薄 HTTP 后,百条级 126ms → 两千条 82ms,批摊销收益随规模上升),63 次嵌入请求、0 失败 0 限流;token 量级估算 ≈0.35–0.45M(短文本按 ~1 token/汉字粗估;网关未暴露单价,成本以 token+墙钟记录,E3)。线性外推 1 万条 ≈13–14 分钟(外推假设未经实测,E2)。单条均耗含建树/索引/快照落库开销,非纯嵌入 HTTP 时间。
2. **是否触碰 §7.2 观测线**:未触碰。指标 2 历史索引占比 36.5% < 80%;指标 4 对象数与快照同阶增长(结构共享有效:tree 4 代导入仅 209 对象);指标 6 hybrid P95(代理)2.9s vs 词法 26–50ms——差距来自外嵌 RTT 而非本地索引结构,段化「读放大 5–10 倍劣化」的观测在向量腿上无踪。**无段化/调优立项依据**。指标 1/3(单条写延迟、写放大)需写路径压测,不在本演练范围。
3. **「语义检索默认开与否」的数据建议**:**维持词法默认 + `--hybrid` 显式旗标**。数据:2000 条档 hybrid 中位 2.431s vs 词法 26ms(≈90×),且 hybrid 强依赖外嵌端点可用性(失败语义=响亮报错不降级);rebuild --embed 2000 条 2.7 分钟属一次性显式成本、可接受,建议保持「显式/定时批处理」定位、不进写热路径(与 §7.3 红线 4 一致)。若未来拟默认开语义,前提是先把查询嵌入 RTT 降下来(缓存/本地小模型),否则默认体验劣化近两个数量级。
4. **§7.2 接入方式**:§4/§5 两表即拟接入的实测行(§5 已给出可直接誊入的一句话行)。验证者纪律(唯一新文件)优先于「结果接入 DESIGN」的字面执行——DESIGN.md 的编辑留待负责人按「一节一件事」流程处理,避免验证会话越权改设计文档。
